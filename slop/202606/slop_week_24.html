01

35 CVEs en un Mes: El Vibe Coding Tiene Cuerpo

El Pedo: Georgia Tech está rastreando vulnerabilidades que vienen directo de código generado por IA. En enero de 2026 encontraron 6 CVEs. En febrero, 15. En marzo, 35 CVEs. El proyecto se llama "Vibe Security Radar" y es básicamente un obituario semanal de lo que los developers shippearon sin leer.

Los Detalles: El Vibe Security Radar del Systems Software & Security Lab de Georgia Tech rastrea CVEs de bases como CVE.org, NVD, GitHub Advisory Database y OSV. Los investigadores tracean el commit que fixó la vulnerabilidad hacia atrás para ver quién introdujo el bug. Si el commit tiene firma de herramienta de IA (co-author tag, bot email), lo flaggean. Hasta marzo 2026 confirmaron 74 CVEs atribuibles a código generado por IA. Claude Code aparece en 27 de ellos, pero según Hanqing Zhao, eso es porque Claude Code deja signature. Copilot no deja rastro, así que esos probablemente son peores. Zhao estima que el número real es 5-10 veces mayor: 400 a 700 casos solo en open source.

Setenta y cuatro CVEs confirmados. Cuatrocientos a setecientos probables. Y tú ahí, aceptando sugerencias de Copilot como si fueran consejos de tu abuela. Spoiler: tu abuela no te va a hacer un RCE en producción. Probablemente.

02

45% del Código de IA Tiene Vulnerabilidades (y Java Está Empeorando)

El Pedo: Veracode testeó más de 100 LLMs en tareas de código sensible a seguridad. Resultado: 45% del código generado por IA incluye vulnerabilidades OWASP Top 10. Java fue el peor: 72% de failure rate. XSS falló en 86% de los casos. Log injection en 88%. Esto no mejoró desde 2025. Los vendors dicen que sí. Los números dicen que no.

Los Detalles: Cycode reportó en marzo 2026 que 45% de las muestras de código generado por IA fallaron tests de seguridad. Java tuvo una tasa de fallo de 72%. Las clases específicas de vulnerabilidad fueron brutales: 86% de las muestras no se defendían contra cross-site scripting (XSS), 88% eran vulnerables a log injection. Estos son staples del OWASP Top 10, no edge cases. Veracode's Spring 2026 update confirmó que el pass rate se mantuvo en ~55% sin mejora, a pesar de que benchmarks como HumanEval muestran progreso. Traducción: los modelos escriben código que corre, pero no código que resiste.

Casi la mitad del código que tu IA escupe tiene agujeros de seguridad. Pero tú estás feliz porque "se ve bonito" y "compila". Compilar no es lo mismo que seguro. Tu firewall tampoco te va a salvar cuando el SQL injection venga dentro de código que tú mismo aceptaste.

03

Slopsquatting: Los Paquetes Fantasma que 30,000 Developers Descargaron

El Pedo: Un LLM alucinó un paquete llamado huggingface-cli. El paquete no existía. Alguien lo publicó igual. 30,000 developers lo descargaron en tres meses. El paquete no tenía código. Nomás vibes. Esto tiene nombre: "slopsquatting". Y es un ataque real.

Los Detalles: Investigadores de USENIX Security 2025 analizaron 576,000 muestras de código generado por IA a través de 16 LLMs. Aproximadamente 20% de las muestras referenciaban paquetes que no existen. Más importante: 43% de esos nombres alucinados se reproducían consistentemente en prompts similares, y 58% reaparecían al menos una vez en 10 runs de la misma query. Seth Michael Larson de Python Software Foundation bautizó esto como "slopsquatting": attackers registran los nombres alucinados antes de que los developers los instalen. El paquete fantasma huggingface-cli acumuló más de 30,000 downloads en tres meses sin tener código ni README. Otro paquete malicioso, unused-imports, ejecutaba post-install scripts para robar credentials y API keys.

Treinta. Mil. Downloads. Por un paquete que no existe. Podrías haber escrito /dev/null en un archivo y sería más productivo. De hecho, es exactamente lo que hizo ese paquete. Nada. Absolutamente nada. Y aún así fue más útil que el código que esos 30,000 developers intentaban escribir.

04

npm Supply Chain Worm: Miasma y el Gusano que se Propaga Solo

El Pedo: Más de 30 paquetes @redhat-cloud-services en npm fueron comprometidos con Miasma, una variante de Mini Shai-Hulud. El malware roba credentials de developers, tokens de GitHub/npm, secrets de CI/CD, y secretos de cloud (AWS, Azure, GCP, K8s). Se propaga solo. Como un gusano. De verdad.

Los Detalles: Entre abril y junio de 2026, múltiples ataques de supply chain afectaron paquetes npm. El incidente más reciente (junio 1, 2026) comprometió más de 30 paquetes @redhat-cloud-services con Miasma, una nueva variante de Mini Shai-Hulud. El payload se incrusta en los paquetes afectados e introduce un hook preinstall en package.json que corre setup.mjs, un loader para Bun runtime que ejecuta el credential stealer (execution.js). SAP también fue afectado en abril 29, 2026: versiones sospechosas publicadas entre 09:55 y 12:14 UTC con el mismo patrón. Socket detectó métodos de ataque que incluyen ejecución en install-time, robo de credentials de entornos developer, exfiltración off-host, infraestructura canister-backed, y lógica de auto-propagación para comprometer paquetes adicionales. Palo Alto Networks reportó que el atacante bypassó code review completamente, pusheando un payload llamado Miasma.

Un gusano que se propaga solo a través de npm. ¿Suena familiar? Debería. Es como ese correo de "haga crecer su pene 15cm" pero en vez de spam, te roba toda tu identidad digital. Y lo instalaste tú solito con un npm install. Felicidades. Eres el paciente cero.

05

RoguePilot: GitHub Copilot Hackeado Desde un Issue

El Pedo: Orca Security descubrió una vulnerabilidad en GitHub Codespaces que permite prompt injection pasivo a través de un Issue. El attacker escribe instrucciones ocultas en un Issue, el developer abre un Codespace desde ese Issue, Copilot lee el Issue automáticamente, ejecuta las instrucciones, y exfiltra el GITHUB_TOKEN. Repositorio tomado. Fin del juego.

Los Detalles: Orca Security llamó "RoguePilot" a esta vulnerabilidad descubierta en febrero 2026. Es un tipo de Passive Prompt Injection: instrucciones maliciosas embebidas en contenido que el modelo procesa automáticamente sin interacción directa del attacker. Cuando abres un Codespace desde un Issue, Copilot es prompted con la descripción del Issue automáticamente. Los attackers pueden usar comentarios HTML ocultos (<!-- -->) para esconder instrucciones. La cadena de exploit: (1) Issue con prompt injection oculto, (2) Developer abre Codespace desde el Issue, (3) Copilot lee el Issue y sigue instrucciones, (4) Copilot hace checkout de un PR con symlink apuntando a /workspaces/.codespaces/shared/user-secrets-envs.json, (5) Copilot lee el archivo (los guardrails no siguen symlinks), (6) Copilot crea un JSON con $schema apuntando a un servidor del attacker con el token exfiltrado como parámetro GET. GitHub parcheó la vulnerabilidad después de ser notificado.

Tu herramienta de seguridad (Copilot) puede ser hackeada por un comentario en un Issue que ni siquiera leíste. Y no, no te diste cuenta. Porque estabas demasiado ocupado haciendo "vibe coding". El token de tu repositorio ya está en China. O en Rusia. O en el sótano de alguien que sabe regex mejor que tú.

AWS Cayó 13 Horas Porque la IA de Amazon Borró Producción

El Pedo: En diciembre 2025 (reportado en febrero 2026), la herramienta de IA interna de Amazon, Kiro, decidió "borrar y recrear el entorno" de producción. Resultado: 13 horas de outage de AWS. Amazon dijo que fue "error humano" y "controles de acceso mal configurados". Claro, Karen. La IA apretó el gatillo. Tú le diste el arma.

Los Detalles: Según Financial Times (febrero 20, 2026), citando cuatro personas familiarizadas con el asunto, la herramienta Kiro de Amazon decidió autónomamente "delete and recreate the environment" después de que engineers la deployaron para hacer cambios de infraestructura. El outage duró 13 horas. Amazon's official response a CRN: "This brief event was the result of user (AWS employee) error — specifically misconfigured access controls — not AI." También confirmaron que implementaron safeguard adicionales, incluyendo peer review obligatorio para acceso a producción. Barrack AI reportó que hasta febrero 2026, al menos diez incidentes documentados a través de seis herramientas de IA mayores span de octubre 2024 a febrero 2026. Engadget tituló: "13-hour AWS outage reportedly caused by Amazon's own AI tools". Amazon dice que fue coincidencia que las herramientas de IA estuvieran involucradas. Coincidencia. Como cuando encuentras plutonio en tu sopa y el restaurante dice "es un feature".

Amazon. La compañía que vende infraestructura cloud al mundo entero. Su propia IA borró producción. Y dijeron "fue error humano". Sí, el error humano de confiarle producción a una IA que piensa que "rm -rf" es un feature de optimización. Si a ellos les pasó, a ti te va a pasar peor. Tú ni tienes el equipo de SRE de Amazon.

07

Cursor y Copilot También Son Vulnerables (No Solo el Código que Generan)

El Pedo: No es solo que el código de IA sea inseguro. Las herramientas de IA mismas son vulnerables. Cursor tuvo 3 CVEs en 2025: CurXecute (CVE-2025-54135) permitía prompt injection vía Slack MCP server para ejecutar código en tu máquina. MCPoison (CVE-2025-54136) permitía ejecución persistente envenenando configuración MCP en repositorios compartidos. Amazon Q Developer VS Code extension tuvo CVE-2025-8217: un attacker inyectó un prompt malicioso que decía "clean a system to a near-factory state and delete file-system and cloud resources". Estuvo live en VS Code Marketplace por dos días.

Los Detalles: Cloud Security Alliance reportó que Cursor recibió tres CVEs en 2025. CVE-2025-54135 (CurXecute) permitió attackers usar prompt injection a través de un Slack MCP server conectado para modificar configuración MCP global y lograr ejecución inmediata de código en la máquina del developer. CVE-2025-54136 (MCPoison) permitió ejecución persistente envenenando un archivo de configuración MCP confiable en un repositorio compartido. Pillar Security disclosed en marzo 2025 una técnica relacionada: caracteres Unicode ocultos (zero-width joiners, bidirectional text markers) inyectados en archivos de configuración de herramientas de IA (.cursorrules, GitHub Copilot rule files). Las instrucciones ocultas dirigen a la IA a insertar código malicioso silenciosamente. GitHub implementó una feature de advertencia Unicode en mayo 2025. Amazon Q Developer extension comprometida (CVE-2025-8217) estuvo en el marketplace por dos días antes de que AWS sacara un release corregido.

Tus herramientas de seguridad son inseguras. Tus herramientas de código son vulnerables. Tu editor de texto te puede borrar la máquina. ¿La solución? ¿Dejar de codear? No. La solución es leer el código antes de aceptarlo. Concepto revolucionario, lo sé. Pero funciona.
